## The recommendation

The VPS keeps three jobs and nothing else:

1. **The clock.** It fires GitHub workflows on time through the API and checks
   that they did their job (`scripts/vps/clock.py`).
2. **The outside watchdog.** The n8n spend governor stays, and an output
   sentinel follows later (`architecture/SENTINEL.md`). Both are pull-only.
3. **The family agents.** Lauren's briefings and the other personal bots stay
   on OpenClaw, untouched (ruling of 2026-09-09).

Everything else retires per the retirement map. At the end, the old box is
replaced with a clean one built from scripts in this repository, rather than
switched off.

## What was found on 2026-10-03

**Lozatron had sent nothing since 25 September, and GitHub was not the cause.**
`krishanraja/lozatron` runs on GitHub Actions. All 33 of its runs from
2026-09-25 21:40 UTC to 2026-10-03 failed in the Test step. A check on the live
delivery ledger only accepted versions 1 and 2. The first send after version 3
shipped wrote a version 3 ledger, so every run after it failed before the brief
could start. Fixed on Lozatron branch `claude/dreamy-einstein-gzxsfg`: the
check now accepts any version the code can read, with a test that what the code
saves always passes it.

**The same run history measured GitHub's scheduler.** The workflow knocks
fourteen times a day. GitHub started about four of them, some six hours late.
COMPOUND saw the same thing: its 05:15 and 06:15 UTC crons started hours late,
and "every run exited as 'outside the window' and still reported success"
(`krishanraja/compound`, `docs/plans/STATE.md`). Hunter fixed it by moving its
clock to Vercel. Every repository that relies on a GitHub schedule has grown
its own workaround, and each one was sized to the last delay seen.

## Why the crons are fragile, and which part a box fixes

| Failure class | Evidence | What fixes it |
|---|---|---|
| **Late or dropped schedules.** A narrow "is it time?" check then exits green with nothing done. | Lozatron, COMPOUND, Hunter (above) | **The clock.** A `workflow_dispatch` sent through the API starts in seconds. The clock fires at the exact local time, reads the proof, and fires once more if the proof is missing. |
| **Green but empty.** A run reports success and produces nothing. | Lozatron's test gate failing for 8 days with nobody noticing. The Vera auditor node disabled since 2026-09-06 while still reading healthy. The Synthesis workflow logging success whatever happened. Gemini fallbacks returning a 404 that rendered green. | **Detection, from outside.** The clock's proof check catches it for what it fires. The sentinel catches it for everything else. The fix itself is always at the source. |
| **Dead credentials** (401s) | The VPS heartbeat, the events lane, the Marcus brief, the n8n Anthropic credentials | **The rotation work already in train.** The box only notices. |
| **Platform limits** | Vercel's 300-second timeout on the judge sweep; the n8n 10k cap | Not this box, apart from the governor counting n8n spend. |

The promise is not that crons stop failing. It is that a late or dropped run is
fired on time and retried by itself, and that anything which cannot retry is
seen within the hour rather than eight days later.

## Why SSH from a cloud session was not used

The cloud container blocks outbound port 22 (tested 2026-10-03) and routes
traffic through a web proxy. The ssh key lives on LORIMER and must never pass
through a chat. Rule R9 already says host actions run from LORIMER over `ssh
openclaw`. So the cloud session builds everything that can be built and
tested, and one prompt on LORIMER does the host work.
