# Experience control-plane hardening

Status: accepted for implementation by Krish Raja on 2026-09-24.

## Evidence

The Mindmake rebuild repeatedly lost accepted component decisions during synthesis, exposed elementary visual defects to Krish before internal QA, treated one-client overlays as durable harness upgrades, and left Claude Cloud and local clients on different generations. The repository test suite still passed because it checked document structure and command-shaped strings without proving that project commands, candidate evidence, release state and surface state were executable and coherent.

## Accepted correction

- Keep the experience-quality and causal scroll-build rules already canaried on Codex.
- Require project-root validation of real state files, feedback ledgers and `package.json` command routes.
- Require a candidate-bound delivery-state receipt carrying every accepted decision, note, evidence item, closure state and exactly one next action.
- Treat an installed one-surface overlay as explicitly provisional until merge, immutable publication, per-surface install and canary evidence complete.
- Make lagging surfaces disclose their stale or blocked state and publish a scheduled fleet-freshness report.
- Keep judges downstream of deterministic identity, continuity, layout, interaction and evidence gates.

## If wrong

These controls could add ceremony without preventing regressions if projects do not execute them. That is why command existence, project paths, artifact digests and negative fixtures are machine checked, and why the scheduled steward must fail on release-state dishonesty.

## Validation

The held-out suite must reject opaque command strings, missing scripts, stale overlays described as durable, lagging surfaces described as healthy, accepted decisions with only `implemented` status, unresolved feedback, candidate digest mismatch and missing evidence files. The full harness suite, surface validator, provenance checker and deterministic release build must pass before publication.

## Rollback

The immediate rollback is the prior immutable harness release. Provisional overlays remain named as such until the replacement release is published and installed.
