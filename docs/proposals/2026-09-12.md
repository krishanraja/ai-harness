# Capture proposal, 2026-09-12

## Hosted observation capture

Krish approved replacing machine-local learning scripts with one hosted,
stateless MCP emitter. The same approval explicitly includes the intermittently
connected second workstation, but the architecture must not depend on that
machine or its mapped drive being online.

The accepted rule records only small, redacted signals after explicit
corrections or material reusable outcomes. It rejects routine-success noise,
raw conversations, sensitive data, machine identity, and direct canon edits.
Tool absence or failure is non-blocking and cannot create a local shadow
ledger. Evidence can reach canon only through human review, regression, and a
governed release.

The alternative was one watcher or scheduled script per workstation, with n8n
as an optional relay. It was rejected because it creates configuration drift,
availability coupling, more credential copies, and silent gaps whenever a
machine or mapped drive is offline.

Validation requires one tool only, separately revocable client identities,
server-owned surface attribution, deterministic retry behavior, strict
redaction, a per-client safety limit, cross-adapter render parity, and held-out
cases for positive capture, routine-success refusal, and honest tool failure.
