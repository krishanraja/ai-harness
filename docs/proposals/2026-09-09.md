## Block 1: repoint `decision-ledger` at `brain/decisions.jsonl`

**Layer decision: (2) skill chapter.** Two rules in `decision-ledger` name a store that has never existed, and a third forbids the only fix. The skill is unusable as written and has been since it was created.

**EVIDENCE**

> `decision-ledger.read-the-schema` and `decision-ledger.capture-or-update-a` name Supabase as the canonical store.

> The skill says return `STORE_UNAVAILABLE` until the store is verified.

> `decision-ledger.apply-the-capture-gate` says do not create an ad hoc permanent file or database.

Counted live against project `gojpffsrxybbpbdzzrvs` on 2026-09-09: **there is no `decisions` table.** Roughly 190 public tables exist and none of them is it. So the skill's canonical store has never existed, and by its own instruction the skill returns `STORE_UNAVAILABLE` for every decision Krish has ever made.

The judge panel, reviewing the commit that created `brain/decisions.jsonl`:

> brain/decisions.jsonl is now a populated permanent decision store while decision-ledger.read-the-schema and decision-ledger.capture-or-update-a still name Supabase as the canonical store and still forbid creating an ad hoc permanent file; the stores.yaml row names the tension but neither rule is superseded, so two live rules now disagree about where decisions live.

> Krish is a recorded asker for the fifteen rulings, but no asker is recorded for standing up a new store ahead of its authorising proposal.

Both are correct. This file is that missing proposal.

**SUPERSEDES**
- `decision-ledger.read-the-schema`, on the location of the canonical store only. The schema it describes is kept.
- `decision-ledger.capture-or-update-a`, on where a captured decision is written.
- `decision-ledger.apply-the-capture-gate` is **not** superseded. Its prohibition on an ad hoc permanent file stands and is what makes this proposal necessary rather than optional: a governed, version controlled, judge reviewed file reached through a proposal is the opposite of ad hoc, and that distinction is the whole argument here.

**ALTERNATIVE EXPLANATIONS**

- **Create the Supabase `decisions` table instead.** This is the reading that keeps every existing rule intact and it is genuinely defensible. Against it: Krish ruled on 2026-09-09 "Both, harness first", and the decisions being stored are rulings about doctrine, which is precisely what the harness governs and Supabase does not. A Supabase table also has no diff, no review and no history, and on the same day it was established that roughly 120 tables in that project were readable by the anonymous key. A decision ledger is the last thing that should live behind a published key.
- **The skill is dead and should be retired, not repointed.** Its store never existed, so arguably nothing was ever lost. Against it: fifteen real rulings now exist and more arrive every session. The need is demonstrated, not hypothetical.
- **The panel is simply wrong that a proposal was needed**, since Krish asked for the ledger directly. Against it: he asked for the decisions to be recorded, not for a specific store to become canonical. The panel is drawing a distinction that holds.

**IF WRONG**

If `brain/decisions.jsonl` is the wrong home, the cost is that decisions live in a git file that agents on non-harness surfaces cannot query without a checkout, where a Supabase table would have been reachable over the API. The n8n fleet would notice first, since it reads Supabase and has no git access. The mitigation already exists in the architecture used for the canon block: git is the source, the database is a rendered projection. Nothing here forecloses adding that projection later.

If the repoint happens and the skill still returns `STORE_UNAVAILABLE` because its verification step is not updated with it, the failure is loud and immediate on the next decision capture, which is the good kind.

**VALIDATION**

- `node scripts/validate-surfaces.mjs` stays green, and `brain/rules.yaml` carries a new `source` for each of the two superseded rules with a `supersedes` link, so the Part B provenance check fails if the edit lands without it.
- The judge panel re-runs on the pull request carrying the skill edit. `contradiction-surfaced` must clear, because after the edit only one rule names a store.
- A decision capture against the repointed skill returns the written row rather than `STORE_UNAVAILABLE`. That is the behavioural test and it has never once passed in the skill's life.
- `brain/stores.yaml` moves `decision-ledger-store` from `migrate` to `canon` in the same change, not before it. That flip is the definition of this proposal being complete, and doing it early is exactly what the panel blocked.

**PRIOR KNOWN-GOOD + ROLLBACK**
