# Stack router

Choose by the observable leak, not the requested tactic.

| Evidence | Primary stack |
|---|---|
| New users fail to reach meaningful value | onboarding |
| Users reach value but make no ownership action | activation |
| Activated users stop returning | retention |
| Qualified users do not choose or keep paid value | monetisation |
| Sessions end before valuable depth | engagement |
| Users value the product but form no self-directed routine | habit-formation |
| Useful output or invitations create little qualified acquisition | growth-viral |
| Users abandon an already-intended consequential action | conversion-optimisation |
| Uncertainty blocks sensitive or consequential action | trust-building |
| Waiting, error, empty, progress, or achievement states damage quality | experience-refinement |
| Setup answers or behaviour fail to shape the experience | intent-shaping |
| Paid value lacks credible differentiation or craft | premium-positioning |

Boundary tests:

- No first value yet: onboarding, not activation.
- First value happened but no investment: activation, not retention.
- Core value is weak: repair product value before retention messaging.
- User does not want the action: research intent before conversion optimisation.
- The request is about aesthetics alone: route to `krish-design`.
- The request is to implement: hand the chosen brief to the build owner.
